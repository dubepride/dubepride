multi-channel platform: a shared tablet kiosk, universal hardware-terminal

## 4. Huawei / non-GMS location: root cause and fix

### 4.1 Symptom

On Huawei/Honor handsets, the signed-in employee’s live location did not reach
the Field Tracker reliably. Manual clocking still worked, and other Android
devices using Google Play Services continued to report. The failure was
isolated to background location acquisition and/or delivery on devices without
a working GMS location stack.

### 4.2 What was tried first

The 6–7 November commits added:

- an Android `LocationManager` fallback alongside the fused provider;
- a native single-fix request that races GMS and `LocationManager`;
- native background listeners for GPS, network, passive and fused providers;
- a foreground service and boot-aware task consumer;
- smoothing, stale-fix rejection and offline queues;
- Huawei/Honor battery and startup settings shortcuts.

Those changes were correct in principle, but they did not fix the installed
APK. That was the critical clue.

### 4.3 Decisive diagnosis

Expo SDK 57 ships `expo-location` as a **prebuilt AAR** by default. The
`expo-module.config.json` file contained an `android.publication` entry, so
Gradle resolved the published artifact instead of compiling the patched Kotlin
sources in `node_modules/expo-location/android/...`.

In practical terms:

- `postinstall` copied the four Kotlin files correctly;
- Gradle still used the stock AAR;
- the Kotlin changes were never compiled;
- the app’s optional native bridge returned `null`, so the UI silently fell
  back to standard location behaviour.

The decisive checks were:

1. Before the fix, `gradlew projects` did **not** list `:expo-location` as a
   Gradle project.
2. After removing `android.publication`, `gradlew projects` listed
   `:expo-location`.
3. `:expo-location:compileReleaseKotlin` then completed successfully.
4. The rebuilt APK’s DEX contained `biobridge-native-v2`,
   `biobridgeGetNativeInfo`, `biobridgeOpenHuaweiStartupSettings` and
   `Native LocationManager registration failed in task consumer`.

That last string proves the custom task consumer was compiled into the APK, not
just the helper module.

### 4.4 The fix

`mobile/scripts/patch-expo-location.js` now performs four jobs on
`postinstall`:

1. Copies the four maintained Kotlin patches into `node_modules`:
   - `LocationHelpers.kt`
   - `LocationModule.kt`
   - `LocationTaskConsumer.kt`
   - `LocationTaskService.kt`
2. Requires the marker **`biobridge-native-v2`** in every copied file.
3. Removes `android.publication` from `expo-location/expo-module.config.json`
   so Gradle compiles from source.
4. Re-reads the config and aborts the build if the publication entry is still
   present or any marker is missing.

The build is intentionally fail-fast. A tree that would silently produce an
APK without the Huawei fallback refuses to build.

> **Important operational note:** `npm install --ignore-scripts` skips the
> postinstall patch. Running it can silently restore the prebuilt AAR and
> remove the Huawei fallback from the next build. Run
> `node scripts/patch-expo-location.js` manually after any install that skips
> scripts.

### 4.5 Native fallback behaviour

The patched engine now has two complementary paths.

**Single fix (`getCurrentPositionAsync`)**

- Uses `LocationManager` directly when Google Play Services is unavailable.
- On GMS devices, races the fused provider and the native provider.
- Returns an ultra-fresh cached fix immediately only when it is under 5 s old
  and accurate to 30 m or better.
- Applies an 8 s live-fix timeout.
- Falls back to a last-known fix up to 10 minutes old before reporting failure.
- Uses GPS, network, passive and `fused` providers where available.

**Continuous background fixes**

- Registers native `LocationManager` listeners for every enabled provider.
- Also registers the GMS fused provider when Play Services is available.
- Uses `minDistance = 0` so a stationary Huawei/Honor phone still receives
  time-based updates.
- Filters duplicate fixes by timestamp.
- Runs a foreground service with `killServiceOnDestroy: false` so swiping the
  app away does not stop sharing.
- Requests high accuracy, `pausesUpdatesAutomatically: false` and
  `distanceInterval: 0`.

The GMS path is retained on Samsung, Redmi and other Play Services devices, so
the fix is additive rather than a replacement. Physical regression testing on
those devices is still outstanding.

### 4.6 Cadence, health and recovery

- Relaxed cadence: **60 s** while idling.
- Armed cadence: **30 s** when a geofence visit is active.
- Presence heartbeat: at most every **30 s** on the phone.
- Server write throttle: one row per employee per **15 s**.
- Presence is treated as stale after **5 minutes**, ignored outside a
  **30-minute** window, and purged after **24 hours**.
- The dashboard checks tracking health on foreground resume and every 30 s
  while sharing is healthy. If Huawei’s power manager killed the task, it
  restarts it.
- “Locate now” forces a high-accuracy fix, falls back to balanced accuracy and
  then to a fix under 120 s old, and publishes it immediately.
- The Android-only “Phone location health” panel shows:
  - precise vs approximate permission;
  - background permission;
  - provider/GPS state;
  - battery-optimisation exemption;
  - whether tracking is running;
  - whether the installed APK contains `biobridge-native-v2`;
  - the last presence heartbeat.
- Huawei/Honor devices get shortcuts to the proprietary App Launch screen plus
  the standard app, location and battery-optimisation settings.

### 4.7 Permissions and lifecycle

- Foreground location must be **Precise**; “Approximate” is rejected because it
  cannot support a geofence verdict.
- “Allow all the time” is strongly recommended. A foreground service can run
  with while-in-use permission on modern Android, but Huawei/Honor and other
  OEM power managers freeze background work without the broader grant.
- Tracking starts on sign-in, on session restore and from the dashboard retry.
- Tracking starts even when no geofence is configured, so the Field Tracker can
  still see the phone.
- Sign-out stops both background tasks, clears the pending presence payload and
  deletes the employee’s remote presence row.
- Manual clocking remains the only punch path. The background engine supplies
  location and visit state; it does not punch automatically.

## 5. Work-tablet kiosk clocking station

Introduced in `600910d` and refined in `1d53845` and `61dff68`.

### 5.1 Purpose

A touch-optimised attendance terminal for:

- shared tablets or stationary phones at site entrances and reception;
- employees who do not have the Android app, including iPhone users;
- sites that need a simple “enter your number and clock” flow without a full
  admin session.

### 5.2 Flow

1. **Standby** — large digital clock, “Enter Employee Number” prompt, on-screen
   keypad and physical-keyboard support.
2. **Lookup** — instant profile lookup by employee number. Shows name,
   department, branch, position, shift, today’s clock state and next direction.
3. **My Profile** — profile card, shift hours and a large one-tap
   **CLOCK IN / CLOCK OUT** button.
4. **Optional PIN** — if the employee has a 4-digit mobile PIN configured, the
   station asks for it before punching.
5. **Confirmation** — punch confirmation with employee name, direction and
   time.
6. **Auto-reset** — returns to standby after 5 seconds, or after 25 seconds of
   inactivity while showing a profile.

Additional UI:

- Fullscreen toggle for wall-mounted tablets.
- “Admin Dashboard” link only when the signed-in account can view the
  dashboard.
- “Sign Out / Admin Login” and “Sign In as Admin” actions.
- The station footer identifies it as the “Work Tablet Attendance Station”.

### 5.3 Server routes

| Route | Purpose |
|---|---|
| `GET /api/tablet/lookup?ref=...` | Resolve employee number, profile, shift, day state and next direction |
| `POST /api/tablet/clock` | Record a verified punch attributed to the tablet station |

Punch attribution:

- `verifyMethod = "Tablet Station"`;
- branch priority: station branch → employee branch → “Main Office”;
- `rawPayload` records employee, station, branch and direction;
- direction uses an explicit `IN`/`OUT` when supplied, otherwise the server
  infers it from the day’s punch sequence.

Both routes require `can_view_tablet_station` (or the dashboard capability) and
return JSON errors, never raw HTML.

### 5.4 Default tablet account

`1d53845` adds a one-time seeded account:

| Field | Value |
|---|---|
| Email | `tablet@biobridge.com` |
| Password | `tablet` |
| Display name | Work Tablet |
| Access level | Tablet Station |
| Branch | First branch at seed time |

The seed is guarded by the `tablet_account_v1` marker, so changing the password
later does not get overwritten on every cold start.

Shorthand login:

- identifier `tablet` maps to `tablet@biobridge.com`;
- blank, `tablet` or `admin` password is accepted for the tablet account;
- identifier `admin` maps to the built-in administrator;
- `admin@biobridge.com` still accepts the configured admin password and the
  legacy `admin` shorthand.

> The default tablet credentials are intentionally simple for deployment. Change
> them after commissioning the station. The seeded branch is the first branch
> in the database; correct it in Settings if the tablet belongs elsewhere.

## 6. Universal terminal configuration and ZKTeco ADMS

Introduced in `e8a9797`, with additional fixes in `61dff68`.

### 6.1 Supported protocols

| Protocol | Intended hardware / transport |
|---|---|
| `ADMS` | ZKTeco, eSSL, BioTime, iClock push |
| `Hikvision` | Hikvision / MinMoe ISAPI HTTP listening |
| `Anviz` | Anviz CrossChex HTTP push / webhook |
| `Suprema` | Suprema BioStar 2 webhook / REST push |
| `Webhook` | Generic JSON, array, CSV or query-string sender |

Terminal configuration now includes:

- protocol;
- serial number (`SN`);
- MAC address;
- IP address and port;
- communication key;
- timezone;
- direction mode — `Auto`, `Device`, `IN_Only`, `OUT_Only`;
- branch and location name;
- status (`Online` / `Offline`);
- optional geofence centre and radius.

### 6.2 ADMS endpoints

| Endpoint | Method | Purpose |
|---|---|---|
| `/iclock/cdata` | `GET` | ADMS handshake / options / keep-alive |
| `/iclock/cdata` | `POST` | ATTLOG attendance push |
| `/iclock/getrequest` | `GET` | Command polling and heartbeat |
| `/iclock/ping` | `GET`/`POST` | Keep-alive alias |
| `/iclock/devicecmd` | `POST`/`GET` | Command execution result |

The handshake returns the standard ADMS option block. Attendance pushes accept
ZKTeco tab-separated rows such as:

```text
1001    2026-11-09 08:02:07    0    1    0    0
```

and key/value forms such as:

```text
ID=1001&Time=2026-11-09 08:02:07&Status=0&Verify=1
```

The universal listener also accepts:

- standard JSON and arrays of JSON;
- Hikvision `AccessControllerEvent` payloads;
- multipart form-data containing JSON;
- CSV lines;
- generic query-string webhooks.

Terminal discovery is automatic. A terminal that pushes with a serial number or
MAC is matched or registered and marked online; its `Last_Ping` is updated on
handshake and polling.

### 6.3 Timezone and direction handling

- Timestamps without an offset are interpreted in the terminal’s configured
  timezone, defaulting to **Africa/Harare (UTC+02:00)**.
- Numeric ZKTeco status codes map to IN/OUT and break states.
- Verify codes map to fingerprint, face, card and similar methods.
- `Direction_Mode` controls whether the device’s own direction is trusted:
  - `Auto` — infer from the punch sequence;
  - `Device` — use the device value, defaulting to IN;
  - `IN_Only` / `OUT_Only` — force the direction.
- The server re-resolves the employee and never trusts a client-supplied branch
  for geofence containment.

### 6.4 Setup guide and diagnostic tester

The Clocking Devices screen now includes a hardware setup modal with:

- copyable `/iclock/cdata` URL;
- copyable `/api/biometrics/push` webhook URL;
- server host/domain and serial-number fields;
- protocol-specific on-device instructions;
- a “Test Handshake” action that marks the terminal online;
- a “Simulate Punch” action that posts a realistic ZKTeco ATTLOG frame.

> The simulated punch is a real ingress request and can create an attendance
> record for `EMP1001`. Use it on a test database or remove the test row
> afterwards.

### 6.5 Operational note

`/iclock` and `/api/biometrics/push` are public by design because hardware
terminals cannot hold a session cookie. This is consistent with the existing
architecture, but it remains an exposure surface. IP allowlisting or a device
secret is recommended for production.

## 7. Authentication, permissions and tablet logout

`61dff68` fixed three related operational problems.

### 7.1 IT Administrator always has full permissions

- The IT Administrator access level is rewritten to the complete permission
  matrix on bootstrap.
- Administrative accounts (`admin@biobridge.com`, `biobridge@it.co.zw`) are
  linked to the IT Administrator level if they are missing it.
- `resolveAccount()` treats an IT Administrator level, or one of those email
  addresses, as all-permissions even if the stored JSON is stale.

This prevents a valid administrator from being locked out of a feature after a
new capability is introduced.

### 7.2 Seamless logout and account switching from the tablet

- The tablet station now calls `POST /api/auth/logout`.
- It then redirects to `/login?switch=1`.
- `/login?switch=1` and `/login?logout=1` bypass the “already signed in”
  redirect, so a tablet-only account can reach the login form.
- A signed-in tablet account without dashboard permission is also allowed to
  view `/login`.
- The station exposes “Sign Out / Admin Login” and “Sign In as Admin”.

### 7.3 No raw 403 pages

`fallbackLanding()` now always returns a readable destination:

1. dashboard, if permitted;
2. tablet station, if permitted;
3. My Portal, if permitted;
4. `/login?switch=1` otherwise.

Page authorization redirects to that landing page. API routes still return
precise `401`/`403` JSON. This removes the previous raw
“Insufficient permissions for this page.” response.

## 8. Field Tracker and mobile presence

Introduced in `a66d8c2` and extended in `e35ec08`, `1f16056` and `15da97b`.

### 8.1 Product behaviour

`/field-tracker` is gated by the dedicated `can_view_live_map` capability,
enforced both by `proxy.ts` for the page and by `requirePermission()` in the
API. IT Administrator and HR Manager receive it by default; Sales Manager does
not. The page shows every tracked phone inside the organisation’s live
geofences:

- branch rail for navigating to any site;
- search by employee number or name;
- selected-employee card with distance from the fence centre;
- directory sorted clocked-in first, then employee number;
- employee number is always the first tooltip line;
- clocked-in is a badge, never a filter;
- stale counts and a map legend;
- the viewport preserves the user’s pan/zoom across polls.

### 8.2 Server-authoritative snapshot

`GET /api/field-tracker` calls `listFieldTracker()`, which builds one snapshot
from:

1. fresh presence;
2. stale presence;
3. latest GPS punch;
4. terminal coordinates;
5. branch centre.

Containment is calculated server-side with Haversine against live
`Branches`/`Terminals` geometry. Overlapping fences resolve to the nearest
centre. A client-reported branch is only a display hint.

The page polls every **10 s**. The mobile app reports at most every **30 s**,
and idle presence is refreshed roughly every **60 s** on newer builds.

### 8.3 Latest position only

`Employee_Presence` holds one row per employee, not a movement history:

- server write throttle: 15 s;
- stale after 5 minutes;
- ignored outside a 30-minute window;
- purged after 24 hours;
- `DELETE /api/mobile/presence` on sign-out removes the row immediately.

The heartbeat enforces the 1-to-1 device binding established at sign-in. A
different phone gets `UNAUTHORIZED_DEVICE`.

### 8.4 Offline behaviour

- If the network is unavailable, the latest fix is stored in AsyncStorage.
- It is uploaded when connectivity returns, when the app returns to the
  foreground, or on the next fix.
- Only the latest fix is retained; there is no unbounded offline history.
- Fixes older than the 30-minute presence window are dropped instead of being
  published as current.
- The dashboard shows a real sharing status, a retry action and a “Locate now”
  recovery action.

### 8.5 Continuous sharing after the 5 November extension

- Tracking starts on sign-in regardless of the `handsFree` flag.
- It works even when no geofence is configured.
- It survives reboot through the persisted background task.
- It stops only on sign-out.
- Android 15/16 safe-area insets are honoured and the map sizes responsively.

## 13. Risks and known limitations

1. **No physical Huawei validation.** The source and APK evidence are strong,
   but the fallback has not been exercised on the actual handset. A device test
   is the only way to close this item.
2. **Huawei model/OS unknown.** If the device is HarmonyOS NEXT, the Android APK
   cannot supply the fallback. Confirm the OS before further native work.
3. **OEM power management is still external.** Even with the correct APK, the
   user must enable auto-launch, secondary launch and background running. The
   dashboard provides shortcuts but cannot force the OEM settings.
4. **`npm install --ignore-scripts` can undo the fix.** It skips the postinstall
   patch and can return Gradle to the prebuilt AAR. The patch must be run
   manually in that case.
5. **No Samsung/Redmi physical regression test.** The GMS path is retained and
   runs alongside the native listeners, but this is a code review conclusion,
   not a device test.
6. **Diagnostic punch is real.** “Simulate Punch” posts a real ATTLOG frame and
   can create an attendance row for `EMP1001`.
7. **Public hardware ingress.** `/iclock` and `/api/biometrics/push` are public
   by design. Add IP allowlisting or a device secret for production.
8. **Default tablet credentials are weak.** Change the tablet password and
   verify its assigned branch after commissioning.
9. **Legacy admin shorthand.** `admin` / `admin` remains intentionally weak for
   the existing demo flow. Change it from Settings → Accounts.
10. **Deployment not verified.** The latest code is committed locally; this
    session did not confirm a Vercel deployment or a production login after
    `61dff68`.
11. **Privacy and consent.** Continuous background location is visible in the
    UI and stops on sign-out, but the organisation should document consent and
    retention policy. Presence history is deliberately not stored.
